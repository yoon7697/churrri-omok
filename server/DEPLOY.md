# 온라인 서버 연결 안내 — 학급 동시 대회

최대 학생 40명이 한 방에서 동시에 오목을 둡니다. 교사는 3·5·7라운드를 선택하고 모든 경기가 종료된 뒤 다음 라운드를 시작합니다. 첫 라운드는 무작위, 이후에는 같은 승점 우선으로 짝을 지으며 점수가 같은 후보 중에는 재대결 횟수가 적은 상대를 우선합니다. 흑백 배정은 누적 흑돌 횟수와 실제 경기 수를 고려합니다.

홀수 인원은 부전승 2점입니다. 현재 접속한 학생 중 부전승 횟수가 가장 적은 학생을 우선하고, 같은 횟수라면 낮은 승점부터 배정합니다. 승리 2점·무승부 1점·패배 0점이며 최종 승점이 같으면 공동순위입니다.

공개 서버: `https://churrri-omok-online.yoon76971.workers.dev`
미리보기: `https://churrri-omok-git-feat-online-server-yoon76971-5417.vercel.app/`
이 미리보기 별칭만 로그인 없이 테스트하도록 설정되어 있습니다. 기존 운영 main은 별도로 유지합니다.

## 배포 준비 상태와 필요한 연결

- 기존 화면: Vercel 유지. 기존 로컬 2인 대결·AI 연습과 화면 체험은 유지합니다.
- 온라인 서버: Cloudflare Workers + SQLite-backed Durable Objects. `server/wrangler.jsonc`에 배포 구성이 있습니다.
- Cloudflare는 GitHub의 `feat/online-server` 브랜치와 연결되어 자동 배포합니다. 새 기능은 별도 검증 브랜치에서 테스트한 뒤 이 배포 브랜치로 반영합니다.
- 계정 비밀번호·API 토큰을 채팅에 붙여 넣을 필요가 없습니다. Cloudflare의 공식 로그인/저장소 연결을 사용합니다.

## Cloudflare에 배포

로컬 개발 환경에서 진행할 경우:

```sh
npm ci
npx wrangler login
npm run deploy:server
```

출력되는 Worker HTTPS 주소를 기록합니다. `--temporary` 임시 계정으로 배포하지 않습니다. 서버 소유권은 사용자의 계정에 둡니다.

Cloudflare 대시보드에서 GitHub 저장소를 연결할 경우 설정값:

| 설정 | 값 |
|---|---|
| 저장소 | yoon7697/churrri-omok |
| 최초 검증 브랜치 | feat/online-server |
| 루트 디렉터리 | 저장소 루트 |
| Worker 이름 | churrri-omok-online |
| 빌드 명령 | npm run build:server |
| 배포 명령 | npx wrangler deploy --config server/wrangler.jsonc |

대시보드 명칭·절차는 바뀔 수 있습니다. 기존 main으로 배포하면 서버 파일이 없는 경우가 있으므로 검증 브랜치를 명시합니다. 운영 반영 때 main으로 전환합니다. 첫 배포에는 Room/Registry의 SQLite 마이그레이션이 생성됩니다. SQLite namespace를 삭제하는 마이그레이션은 추가하지 않습니다.

## Vercel 화면과 연결

Worker 배포 후 생성된 HTTPS origin을 `ONLINE_API_BASE` 환경 변수로 Vercel의 해당 미리보기 환경에 지정합니다. 개인정보나 비밀값이 아니라 서버 주소입니다.

Vercel의 Build Command를 `npm run configure:online`으로 설정하고 재배포합니다. 이 명령은 `live/config.js`에 서버 주소만 기록합니다. 기존 Framework Preset Other/정적 출력 설정을 유지합니다. 공개 코드에 자격 토큰을 넣지 않습니다.

대안으로 서버 주소를 확인한 뒤 저장소의 `live/config.js`에 `API_BASE`를 그 HTTPS origin으로 설정해 반영할 수 있습니다. 위 두 방식 중 하나를 선택합니다.

서버의 `ALLOWED_ORIGINS`에는 실제로 사용하는 Vercel 프런트엔드 origin을 정확하게 등록합니다. 현재 운영 주소와 이번 기능 브랜치 미리보기 주소를 명시했습니다. 모든 vercel.app 주소를 허용하거나 CORS를 `*`로 열지 않습니다. 커스텀 도메인을 쓰면 그 origin을 별도로 추가합니다.

## 실제 기기 확인

1. 교사 기기에서 `?online=1&role=teacher`로 진입해 실제 방 만들기.
2. 방 코드 아래의 **QR코드 크게 보기**를 전자칠판에 제시. 학생은 카메라로 스캔해 닉네임으로 참가합니다. 학생 입장 링크 복사도 사용할 수 있습니다.
3. 학생 두 명 이상이 연결되면 교사가 대결 시작.
4. 두 판의 착수·차례·마지막 수, 3·3 금수, 승패·점수·종료 후 이름 공개 확인.
5. 학생 새로고침, 잠깐 와이파이 끊기, 교사 새로고침 후 같은 경기 복귀 확인.
6. 5분 종료 시 무승부, 교사의 다음 라운드 시작, 접속이 끊긴 학생은 다음 매칭에서 제외되고 복귀하면 다음 라운드에 참여하는지 확인.

서버 주소가 비어 있으면 기존 홈은 화면 체험을 유지합니다. `?online=1` 진입은 연결 준비 안내만 보여 주며 가짜 연결 성공을 표시하지 않습니다. 서버 연결 후 홈의 방 만들기/입장이 실제 서버로 이동합니다. `?demo=1`에서는 기존 예시 방 4827을 계속 검토할 수 있습니다.

## 테스트

```sh
npm test
npm run test:server
LIVE_TEST_SERVER=1 npm run test:ui
```

`test:server`는 번들 생성 후 순수 규칙·권한·시간 모델과 Miniflare 실제 Durable Object/WebSocket/SQLite 영속성 테스트를 실행합니다. 브라우저 통합 검증은 로컬 Cloudflare 런타임과 교사/학생의 분리된 브라우저 저장소를 사용합니다. 브라우저 테스트에서 서버 주소 파일만 로컬 서버로 설정하며 게임 API·착수 응답은 모의 처리하지 않습니다.

`npm run dev:server`는 로컬 디버깅용 Wrangler 서버입니다. 브라우저 테스트는 별도 Miniflare 서버를 자동으로 시작합니다. 배포 전 `npx wrangler deploy --config server/wrangler.jsonc --dry-run`으로 설정·번들을 검증할 수 있습니다.

## 현재 보장하는 처리

- 서버와 브라우저가 같은 저장소의 `rules.js`를 사용합니다. 클라이언트의 승패·점수 선언은 받지 않습니다.
- 방 코드와 교사 권한은 별개입니다. 256비트 무작위 자격을 브라우저가 만들고, 서버는 SHA-256 해시만 저장합니다.
- 장기 자격은 HTTPS Authorization으로만 전송합니다. WebSocket에는 20초 유효·1회용 연결 티켓을 사용합니다. 자격·티켓을 로그로 출력하지 않습니다.
- 허용 origin 검사, 생성·입장·연결 요청 제한, 메시지 길이·빈도 제한을 적용합니다.
- 4자리 코드는 중앙 Registry에서 중복 없이 배정합니다. 생성 후 2시간 동안 입장 가능하고, 재사용 유예는 추가 24시간입니다.
- 방 상태 변경·5분 기한·결과·요청 영수증을 저장한 뒤에만 확정 상태를 전달합니다. 저장 오류가 있으면 성공으로 알리지 않습니다.
- 같은 요청 번호 재전송은 저장된 처리 여부로 중복 실행을 막습니다. 최근 2,000건을 보관하며, 착수는 경기 ID·착수 번호·차례도 검사합니다.
- 경기 중 학생에게는 자기 오목판과 다른 경기의 익명 현황만 전송합니다. 관전 자격이 있는 학생이 선택하면 그 관전 판 하나를 추가로 전송하고, 진행 중인 상대 이름·참가 ID는 숨깁니다. 끝난 경기의 이름은 공개합니다. 학생 명단은 모든 경기가 끝난 뒤 다시 표시합니다.
- 교사는 경기 목록과 참가 명단에서 대진을 확인하고 이름 변경·입장 잠금·내보내기·무승부 종료·방 닫기를 실행할 수 있습니다.
- 서버가 각 경기의 5분 기한을 저장하고 가장 이른 기한으로 알람을 설정합니다. 알람과 모든 요청에서 모든 경기의 마감을 검사합니다. 알람이 지연돼도 기한 후 착수를 받지 않습니다. 결과·점수는 경기당 한 번만 확정합니다.
- 같은 참가 자격으로 새 탭을 열면 이전 연결을 무효화합니다. 이전 탭이 새 경기로 자동 재접속해 연결을 빼앗지 않습니다.
- 접속이 끊기면 입력을 막습니다. 클라이언트의 미확인 착수를 오프라인 대기열에 넣지 않고 서버 스냅샷으로 복구합니다.
- 대기 중 컴퓨터 연습은 실제 AI를 사용합니다. 선생님의 시작 이벤트를 받으면 AI Worker를 취소하고 온라인 경기로 이동합니다.
- 방은 2시간 후 닫히며 결과는 생성 후 최대 26시간, 직접 닫은 경우 닫은 뒤 24시간 후 삭제합니다.

## 아직 검증/구현하지 않은 범위

학교 Wi-Fi·Safari/iPad 실기기에서 40명이 동시에 사용하는 성능과 실제 카메라 QR 스캔은 별도로 확인해야 합니다. 교사 승인 기기 변경 복구는 아직 구현하지 않았습니다. QR 생성·확대·주소 해독·참가는 자동 검사로 확인했습니다. 관전은 같은 방의 현재 라운드 경기만 제공합니다.

참가 자격은 같은 브라우저 저장소에 보관합니다. 저장소 삭제·비공개 모드 종료·다른 기기 이동은 자동 복구되지 않습니다. 방을 다시 만드는 경우 기존 참가 자격을 닉네임만으로 넘기지 않습니다.

## 다인 경기 데이터와 복구

각 경기는 라운드 번호·경기 번호·독립된 판·차례·5분 마감·결과를 가집니다. 한 판 종료는 그 두 명에게만 점수를 반영하고, 나머지 활성 경기가 있으면 라운드를 계속 진행합니다. 학생은 자기 경기 ID로만 착수할 수 있으며 교사는 특정 경기만 또는 진행 중인 경기 전부를 무승부 종료할 수 있습니다. 내보내기는 해당 학생의 진행 중 경기만 종료합니다.

라운드 시작 순간 접속 중인 학생만 배정합니다. 중간 입장 또는 매칭 당시 미접속 학생은 다음 라운드 안내와 AI 연습을 이용합니다. 이미 배정된 학생이 재접속하면 5분 기한 안에서 자기 판으로 돌아옵니다. 기한은 재접속으로 연장되지 않습니다. 기존 두 학생 방은 같은 저장 형식을 읽으며 SQLite namespace 삭제나 파괴적 마이그레이션을 하지 않습니다.

학교의 한 공인 IP를 함께 쓰는 상황을 고려해 학생 입장 요청은 분당 120회, 상태/티켓/실시간 연결 경로는 분당 600회로 제한합니다. 실제 학생 정원은 40명, 내보낸 학생을 포함한 참가 기록은 방당 최대 80명입니다.

## 실시간 관전

경기가 끝난 학생, 부전승 학생, 중간 입장/복귀 후 다음 라운드 대기 학생은 익명 경기 목록에서 다른 판을 선택해 관전할 수 있습니다. 자기 경기가 진행 중이면 관전 선택을 서버에서 거절합니다. 교사는 어느 현재 경기도 선택할 수 있습니다.

`watch` / `unwatch` 명령으로 참가자별 관전 선택을 영속 저장하며, 재접속·새로고침·서버 런타임 복구 때 같은 판을 복원합니다. 스냅샷의 `spectating`에 선택된 판 하나만 전송합니다. 관전 화면의 칸은 모두 비활성화하고 클릭 핸들러를 부착하지 않습니다. 서버의 착수 권한은 원래 두 선수에게만 있으므로 조작한 클라이언트의 요청도 거절합니다.

학생에게는 진행 중인 관전 경기의 이름·참가 ID를 보내지 않고, 종료 후 동결된 이름과 중립적인 승패 결과를 공개합니다. 학생 자신의 결과와 점수는 관전으로 바뀌지 않습니다. 교사는 기존 관리 권한대로 이름을 확인합니다. 다음 라운드 시작 시 모든 관전 선택을 지우고 학생의 새 경기/부전승/대기 상태로 자동 전환합니다. 닫힌 방·내보내진 학생·이전 라운드·다른 방의 경기에는 관전 접근을 허용하지 않습니다.


## QR 초대와 최종 공개 점검

교사 대기실에서 QR코드를 크게 띄우면 학생용 참가 주소와 방 코드만 공유합니다. 교사 자격은 포함하지 않습니다. QR 생성은 번들에 포함한 라이브러리로 브라우저에서 실행하며 외부 QR 생성 API에 의존하지 않습니다. 같은 방의 QR을 다시 열면 기존 학생으로 복귀하고, 다른 방의 QR이면 새 참가 화면을 표시합니다.

[최종 점검 기록과 실제 기기 확인 순서](../docs/RELEASE-CHECK.md)를 참고하세요. 정식 배포 전에는 현재 미리보기 별칭을 사용합니다. 운영 주소는 이미 서버의 허용 origin 목록에 포함되어 있습니다. 브랜치 병합 후 화면과 서버의 실제 배포 성공을 각각 확인해야 합니다.
