# 온라인 서버 연결 안내 — 학생 2명 검증 단계

이번 브랜치는 방 생성 → 두 학생 참가 → 실시간 오목 → 서버 판정 → 새로고침·재접속 복구까지 구현합니다. 교사는 3·5·7회 대결을 진행할 수 있습니다. 학급 전체의 자동 매칭·부전승·관전·최종 공동 순위 화면은 다음 단계입니다. 온라인 방 정원은 현재 **학생 두 명**입니다.

## 배포 준비 상태와 필요한 연결

- 기존 화면: Vercel 유지. 기존 로컬 2인 대결·AI 연습과 화면 체험은 유지합니다.
- 온라인 서버: Cloudflare Workers + SQLite-backed Durable Objects. `server/wrangler.jsonc`에 배포 구성이 있습니다.
- 이 작업 환경에는 Cloudflare에 로그인된 배포 자격이 없습니다. 계정 연결 전에는 공개 기기 간 대결을 제공했다고 표시하지 않습니다.
- 계정 비밀번호·API 토큰을 채팅에 붙여 넣을 필요가 없습니다. Cloudflare의 공식 로그인/저장소 연결을 사용합니다.

## Cloudflare에 배포

로컬 개발 환경에서 진행할 경우:

```sh
npm ci
npx wrangler login
npm run deploy:server
```

출력되는 Worker HTTPS 주소를 기록합니다. `--temporary` 임시 계정으로 배포하지 않습니다. 서버 소유권은 사용자의 계정에 둡니다.

Cloudflare 대시보드에서 GitHub 저장소를 연결할 경우 설정값:

| 설정 | 값 |
|---|---|
| 저장소 | yoon7697/churrri-omok |
| 최초 검증 브랜치 | feat/online-server |
| 루트 디렉터리 | 저장소 루트 |
| Worker 이름 | churrri-omok-online |
| 빌드 명령 | npm run build:server |
| 배포 명령 | npx wrangler deploy --config server/wrangler.jsonc |

대시보드 명칭·절차는 바뀔 수 있습니다. 기존 main으로 배포하면 서버 파일이 없는 경우가 있으므로 검증 브랜치를 명시합니다. 운영 반영 때 main으로 전환합니다. 첫 배포에는 Room/Registry의 SQLite 마이그레이션이 생성됩니다. SQLite namespace를 삭제하는 마이그레이션은 추가하지 않습니다.

## Vercel 화면과 연결

Worker 배포 후 생성된 HTTPS origin을 `ONLINE_API_BASE` 환경 변수로 Vercel의 해당 미리보기 환경에 지정합니다. 개인정보나 비밀값이 아니라 서버 주소입니다.

Vercel의 Build Command를 `npm run configure:online`으로 설정하고 재배포합니다. 이 명령은 `live/config.js`에 서버 주소만 기록합니다. 기존 Framework Preset Other/정적 출력 설정을 유지합니다. 공개 코드에 자격 토큰을 넣지 않습니다.

대안으로 서버 주소를 확인한 뒤 저장소의 `live/config.js`에 `API_BASE`를 그 HTTPS origin으로 설정해 반영할 수 있습니다. 위 두 방식 중 하나를 선택합니다.

서버의 `ALLOWED_ORIGINS`에는 실제로 사용하는 Vercel 프런트엔드 origin을 정확하게 등록합니다. 현재 운영 주소와 이번 기능 브랜치 미리보기 주소를 명시했습니다. 모든 vercel.app 주소를 허용하거나 CORS를 `*`로 열지 않습니다. 커스텀 도메인을 쓰면 그 origin을 별도로 추가합니다.

## 실제 기기 확인

1. 교사 기기에서 `?online=1&role=teacher`로 진입해 실제 방 만들기.
2. 학생 입장 링크 복사. 서로 다른 두 학생 기기에서 열고 닉네임으로 참가.
3. 학생 두 명이 연결되면 교사가 대결 시작.
4. 두 판의 착수·차례·마지막 수, 3·3 금수, 승패·점수·종료 후 이름 공개 확인.
5. 학생 새로고침, 잠깐 와이파이 끊기, 교사 새로고침 후 같은 경기 복귀 확인.
6. 5분 종료 시 무승부, 교사의 다음 라운드 시작, 접속이 끊긴 학생이 복귀하기 전 시작 차단 확인.

서버 주소가 비어 있으면 기존 홈은 화면 체험을 유지합니다. `?online=1` 진입은 연결 준비 안내만 보여 주며 가짜 연결 성공을 표시하지 않습니다. 서버 연결 후 홈의 방 만들기/입장이 실제 서버로 이동합니다. `?demo=1`에서는 기존 예시 방 4827을 계속 검토할 수 있습니다.

## 테스트

```sh
npm test
npm run test:server
LIVE_TEST_SERVER=1 npm run test:ui
```

`test:server`는 번들 생성 후 순수 규칙·권한·시간 모델과 Miniflare 실제 Durable Object/WebSocket/SQLite 영속성 테스트를 실행합니다. 브라우저 통합 검증은 로컬 Cloudflare 런타임과 교사/학생의 분리된 브라우저 저장소를 사용합니다. 브라우저 테스트에서 서버 주소 파일만 로컬 서버로 설정하며 게임 API·착수 응답은 모의 처리하지 않습니다.

`npm run dev:server`는 로컬 디버깅용 Wrangler 서버입니다. 브라우저 테스트는 별도 Miniflare 서버를 자동으로 시작합니다. 배포 전 `npx wrangler deploy --config server/wrangler.jsonc --dry-run`으로 설정·번들을 검증할 수 있습니다.

## 현재 보장하는 처리

- 서버와 브라우저가 같은 저장소의 `rules.js`를 사용합니다. 클라이언트의 승패·점수 선언은 받지 않습니다.
- 방 코드와 교사 권한은 별개입니다. 256비트 무작위 자격을 브라우저가 만들고, 서버는 SHA-256 해시만 저장합니다.
- 장기 자격은 HTTPS Authorization으로만 전송합니다. WebSocket에는 20초 유효·1회용 연결 티켓을 사용합니다. 자격·티켓을 로그로 출력하지 않습니다.
- 허용 origin 검사, 생성·입장·연결 요청 제한, 메시지 길이·빈도 제한을 적용합니다.
- 4자리 코드는 중앙 Registry에서 중복 없이 배정합니다. 생성 후 2시간 동안 입장 가능하고, 재사용 유예는 추가 24시간입니다.
- 방 상태 변경·5분 기한·결과·요청 영수증을 저장한 뒤에만 확정 상태를 전달합니다. 저장 오류가 있으면 성공으로 알리지 않습니다.
- 같은 요청 번호 재전송은 저장된 처리 여부로 중복 실행을 막습니다. 최근 2,000건을 보관하며, 착수는 경기 ID·착수 번호·차례도 검사합니다.
- 학생의 진행 중 상태에는 상대 닉네임·상대 참가 ID·승점·명단 대응을 전송하지 않습니다. 2명 대결에서 상대를 현실적으로 추측하는 것까지 막지는 못합니다.
- 교사는 항상 대진을 확인하고 이름 변경·입장 잠금·내보내기·무승부 종료·방 닫기를 실행할 수 있습니다.
- 서버가 5분 기한을 저장하고, 알람과 모든 요청에서 마감을 검사합니다. 알람이 지연돼도 기한 후 착수를 받지 않습니다. 결과·점수는 경기당 한 번만 확정합니다.
- 같은 참가 자격으로 새 탭을 열면 이전 연결을 무효화합니다. 이전 탭이 새 경기로 자동 재접속해 연결을 빼앗지 않습니다.
- 접속이 끊기면 입력을 막습니다. 클라이언트의 미확인 착수를 오프라인 대기열에 넣지 않고 서버 스냅샷으로 복구합니다.
- 대기 중 컴퓨터 연습은 실제 AI를 사용합니다. 선생님의 시작 이벤트를 받으면 AI Worker를 취소하고 온라인 경기로 이동합니다.
- 방은 2시간 후 닫히며 결과는 생성 후 최대 26시간, 직접 닫은 경우 닫은 뒤 24시간 후 삭제합니다.

## 아직 검증/구현하지 않은 범위

Cloudflare 계정 실제 배포, 공개 네트워크·학교 Wi-Fi·Safari/iPad 실기기 성능은 별도로 확인해야 합니다. 초기 검증의 학생 수는 2명이며 다인 자동 매칭·부전승·관전·대기 학생 라운드 합류·공동 순위 UI는 아직 제공하지 않습니다. 교사 승인 기기 변경 복구와 QR 초대도 후속 단계입니다.

참가 자격은 같은 브라우저 저장소에 보관합니다. 저장소 삭제·비공개 모드 종료·다른 기기 이동은 자동 복구되지 않습니다. 방을 다시 만드는 경우 기존 참가 자격을 닉네임만으로 넘기지 않습니다.
