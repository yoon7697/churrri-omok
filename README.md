# 우리 반 오목왕 v0.3.0 — 컴퓨터 연습

v0.2.1의 메인 일러스트, 로컬 2인 대결, 전용 게임 화면, 금수·승패 팝업을 유지하면서 컴퓨터 연습을 추가했습니다. 온라인 방·참가·대회 기능은 아직 구현하지 않았습니다.

## 사용 방법

- **연습하기** → 난이도와 내 돌 선택 → **연습 시작하기**
- 기본값은 **보통 / 흑돌**입니다. 백돌을 고르면 컴퓨터가 먼저 시작합니다.
- 컴퓨터가 생각하는 동안 착수는 잠깐 막히지만 메인 이동·새 게임·무르기는 작동합니다.
- 연습의 **내 차례로 무르기**는 컴퓨터 응답까지 취소합니다. 컴퓨터가 생각 중이라면 방금 둔 내 수만 취소합니다. 백돌로 연습할 때 컴퓨터의 첫 수는 유지합니다.
- 새 게임은 현재 난이도·돌 색을 유지합니다. 설정을 바꾸려면 메인 → 연습하기로 돌아갑니다.
- 1:1 대결의 한 수 무르기는 기존처럼 마지막 돌 하나를 취소합니다.

## 규칙

`rules.js`와 기존 28개 규칙 테스트는 v0.2.1에서 변경하지 않았습니다.

- 15×15, 흑돌 선공, 흑백 모두 3·3 금지
- 연속 5개 이상이면 승리, 5목 완성이 3·3보다 우선
- 4·4·장목 허용, 금수 착수는 무효이며 차례 유지
- 판이 가득 차면 무승부
- 예외적으로 컴퓨터의 합법 착수가 하나도 없으면 연습을 무승부로 종료합니다.

학교용 사용자 정의 규칙이며 공식 렌주 규칙과 다릅니다. 복잡한 3·3 예외 전부를 검증한 공식 심판 엔진은 아닙니다.

## 컴퓨터

| 난이도 | 방법 | 최대 탐색 깊이 | 탐색 시간 예산 |
| --- | --- | --- | --- |
| 쉬움 | 공격·방어 점수, 비긴급 상황에서 가끔 차선 선택 | 1수 | 점수 계산 |
| 보통 | 제한 후보 Minimax / Alpha-Beta | 2수 | 300ms |
| 어려움 | 반복 심화 Minimax / Alpha-Beta | 3수 | 900ms |

모든 난이도는 자신의 즉시 승리와 상대의 즉시 승리를 우선 확인하고, 열린 삼·열린 사·띄엄 패턴을 점수화합니다. 기존 돌 주변 두 칸을 후보로 삼으며 합법 후보가 없으면 전체 판을 검사합니다. 후보 수는 탐색 시 최대 8개이며, 기기 속도에 따라 끝까지 완료한 탐색 깊이를 사용합니다. 완전 탐색이나 무패 AI가 아닙니다.

계산은 모듈 Web Worker에서 실행합니다. 시간 예산은 탐색 노드 사이에서 확인하므로 마지막 노드 계산만큼 넘길 수 있습니다. 240ms의 짧은 생각 표시 후 시작하며, 5초 이내 응답이 없거나 Worker를 쓸 수 없으면 합법적인 기본 착수로 복구합니다. 최종 착수는 화면에서도 기존 규칙 엔진으로 재검사합니다. 무르기·새 게임·메인 이동은 Worker와 대기 타이머를 취소합니다.

## 실행 및 배포

런타임 외부 서비스·API 키가 필요 없는 정적 사이트입니다.

```sh
python3 -m http.server 8080
```

`http://localhost:8080`에서 확인합니다. 파일을 더블클릭하는 `file://` 방식은 모듈·Worker를 실행할 수 없습니다.

Vercel 설정: Framework Preset **Other**, 루트 `./`, 빌드 명령 없음, 출력 디렉터리 `.`. 기존 GitHub 연동을 유지할 수 있습니다. 기능 브랜치의 미리보기에서 확인한 뒤 main에 병합하면 운영 배포됩니다.

## 자동 검증

```sh
npm ci
npm test
npx playwright install chromium
npm run test:ui
```

규칙·AI 테스트는 Node의 기본 테스트 도구로 실행합니다. 화면 검증은 Playwright를 사용합니다. 설치된 Chromium으로 실행하려면 `CHROMIUM_PATH=/path/to/chromium npm run test:ui`를 사용할 수 있습니다. GitHub Actions에도 동일한 검증을 구성했습니다.

- 규칙·AI: 기존 규칙, 양 색·세 난이도 즉시 승리/방어, 금수 회피, 열린 삼/사 공격·방어, 판 보존, 시간 예산 종료, 합법 대국 진행, 무승부
- 브라우저: 실제 Worker의 여섯 설정 조합, 무르기·새 게임·메인 이동 중 취소, 로컬 금수/승리/무승부, 연습 결과, Worker 실패 복구
- 연습의 승리 팝업 시나리오는 컴퓨터 수만 고정한 테스트이며 실제 AI 대국 강도 검증과 구분됩니다.
- 화면 크기: 390×844, 768×1024, 1024×768, 1366×768, 844×390. 에뮬레이션 검증은 실제 iPad/Android 기기 테스트를 대체하지 않습니다.

## 온라인 대기실 화면 미리보기 (서버 연결 전)

이번 브랜치는 **온라인 대회의 첫 화면 단계**입니다. 다른 기기와 연결하거나 실제 대회를 진행하는 서버는 아직 연결하지 않았습니다. 화면에 이 한계를 명시하고, 예시 방 코드 **4827**을 사용합니다. 운영 반영 전 별도 브랜치의 Vercel 미리보기로 검토합니다.

### 확인 순서

1. 메인 → **방 만들기** → 3·5·7라운드 선택 → **체험 방 만들기**
2. 교사 대기실 → **예시 학생 추가** → 학생 카드 클릭 → 이름 변경 또는 내보내기
3. **입장 열림/잠김** 전환, 코드 복사, 체험 방 닫기 확인
4. **학생 화면 체험** → 코드 4827·닉네임 입력 → 학생 대기실
5. 학생 대기실 → **컴퓨터와 연습하기** → 실제 v0.3 AI 대국 → **대기실로** 복귀

학생 화면만 확인하려면 메인에서 **방 코드로 참가** → 예시 코드 입력을 이용합니다. 기본 예시 학생 6명이 있는 방을 보여줍니다. 교사 체험 방은 처음에 빈 대기실로 시작합니다.

- 체험 상태는 이 탭의 sessionStorage에만 저장합니다. 다른 탭·기기로 전송하지 않습니다. 저장소를 사용할 수 없어도 화면 체험은 가능하며 새로고침 시 초기화될 수 있다고 안내합니다.
- 교사/학생 역할 전환 버튼은 **체험 도구**입니다. 실제 교사 인증 기능이 아닙니다.
- 닉네임은 2~12자, 공백 정리, 중복 방지. HTML 문자열도 텍스트로 표시합니다.
- QR 초대, 대회 시작, 온라인 매칭·관전·승점·재접속은 다음 서버 단계입니다. 사용 가능한 기능처럼 위장한 버튼이나 가짜 QR은 제공하지 않습니다.
- 기존 규칙 엔진·AI와 로컬 대결은 변경하지 않았습니다. app.js에는 대기실에서 연습을 시작하고 돌아오는 연결부만 추가했습니다.

## 실제 온라인 연결 — 학생 2명 검증 단계

후속 서버 브랜치에는 Cloudflare Durable Objects 서버와 실제 온라인 화면을 추가했습니다. 공개 서버 배포 전에는 기존 화면 체험을 유지하며, 서버가 연결된 것처럼 표시하지 않습니다.

교사 방 생성·학생 두 명 입장·실시간 착수·3/5/7회 교사 진행·5분 마감·점수·이름 공개·재접속 복구를 구현합니다. 학생 연습 중 교사가 시작하면 온라인 경기로 이동합니다. 다인 자동 매칭·부전승·관전·공동 순위 UI는 이후 단계입니다.

설정·배포·실제 기기 확인·검증 범위는 [server/DEPLOY.md](server/DEPLOY.md)에 정리했습니다. 서버 주소 연결 후 홈에서 실제 방을 만들 수 있고, `?online=1&role=teacher` 또는 `?online=1&role=student`로 바로 들어갈 수 있습니다. `?demo=1`은 기존 예시 대기실을 유지합니다.


## 실제 대회 QR 초대

교사 대기실의 방 코드 아래에 학생 입장용 QR코드를 표시합니다. **QR코드 크게 보기**를 누르면 전자칠판에 제시할 큰 QR코드와 4자리 방 코드가 나옵니다. 학생은 스캔 후 닉네임을 입력하면 해당 방에 참가합니다. 학생 대기실·경기·결과 화면에는 초대용 QR이나 방 코드가 나오지 않습니다.

- QR과 링크 복사는 같은 학생용 주소를 사용하며 교사 토큰·관리 권한·기존 쿼리 정보는 포함하지 않습니다.
- QR은 브라우저에서 생성합니다. 외부 QR 생성 API나 CDN 요청이 필요하지 않습니다. 입장 잠금·정원·방 종료 여부는 기존 서버가 검증합니다.
- `live/invite.js`는 학생용 주소와 QR을 생성하고 `live/vendor/qrcode.js`는 MIT 라이선스의 qrcode-generator 2.0.4를 포함합니다. 의존성 설치 후 `npm run build:qr`로 번들을 다시 생성할 수 있습니다.
- 브라우저 검사에서는 생성된 QR을 이미지로 읽어 실제 주소를 해독하고, 그 주소를 새 학생 브라우저에서 열어 참가·클립보드·휴대폰 화면·닫기 동작을 확인합니다. 실제 태블릿 카메라 스캔은 별도로 확인해야 합니다.
